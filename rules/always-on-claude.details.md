# Always-on rules for Claude Code: procedures

Companion to [`always-on-claude.md`](always-on-claude.md). Each section is read when its rule applies or when the named hook refuses an action. The hooks belong to the `orch` plugin ([`orch/hooks/`](../orch/hooks)).

## Gates

- Plan opening lines: `plan-simplify-gate` reads the plan text (ExitPlanMode `tool_input.plan`, judged before any transcript read, else the last plan file written) and refuses it unless `Task:`, `Done when:` and `Existing:` with non-empty values stand among its first 6 head lines, in any order; a value is the label's line plus the list items or indented lines directly under it (after at most one blank line), which are not head lines; head lines are the other non-blank lines; markdown marks and a wholly `[...]`/`<...>` placeholder count as empty, nothing else in a value is parsed; deterministic, no model call; checked before the `/simplify` freshness rule.
- Question to the owner: `ask-existing-gate` (PreToolUse on AskUserQuestion) passes a call when a line of some question stem starts with `Existing:` with a non-empty value (the plan gate's value rule), or when `metadata.source` holds the clause `existing: n/a` (a question that offers no definition or mechanism: a confirmation, a permission, a priority); a citation only in `metadata.source` does not pass, because the owner never sees metadata. Otherwise it refuses with the measured text; per call, no session state; fails open on a malformed payload. `metadata.source` is a list of `key: value` clauses separated by `;`, in any order (`gate_policy.source_clauses`); a refusal asks to add a clause and keep the ones there. Its spend rule runs first: a call whose stems or options hold a currency amount or a pay, buy, rent or price word goes to a small-model judge (`claude -p --model haiku` on the session's own login, 25 s, fail open; every judged call logged to `~/.claude/ask-existing-gate-log.jsonl`) asking whether choosing the stem or any option makes our company pay money actually charged; a model, labelling or eval run counts only when the text bills it to a metered key or a paid outside service. On yes the call is refused (`spend rule`) unless it holds one question whose stem has a `Spend:` line with every slot filled: a sum and a `ceiling` with numbers, `account:`, `left` and `later:` with real values (`none` allowed for later). A question that spends nothing is reworded to say who pays, never given a `Spend:` line.
- Dialog right after a pinned question: before its other rules, `ask-existing-gate` refuses an AskUserQuestion while the session's open-question file holds a pin and the transcript shows nothing written after the file's last write but notifications and dialogs a hook refused or that failed, unless `metadata.source` holds a non-empty `blocked:` clause. A main-session tool call written after the pin, a dialog the owner dismissed or rejected, an empty file (an answered dialog, a typed owner prompt and a stop with nothing running clear it), a subagent payload and a read cut by the bound (12 MB) pass. The running assistant message is not on disk, so a call in the dialog's own message is not seen: that dialog is refused once and a bare retry passes once the message is written; a bare retry with no work since the pin is refused again.
- Real-path check before a change reaches a shared path: service start plus one unit through natively, against the shared local store container or a production read route, never a container per task; on a numeric path also the target before/after. The merge command carries `CHECK_RAN: <what ran, result>`, `PROD_POSITION: <blast-radius dimension, production's number, source>`, `WAY_BACK: <undo, minutes>` and `WORSE_FOR: <who gets worse or can break for every consumer, the new bottleneck; or none, with the reason>`, plus `ALWAYS_ON: <before> -> <after> chars` (wc -c) with `removed: <text cut>` or `reason: <why it must grow>` when it grows an always-on rules file (`rules/always-on.md`, `rules/always-on-claude.md`), or `merge-gate` refuses it.
- Stop hook `reply-lint`: returns once a reply that leaves work waiting on the owner's choice, answer or approval in plain text (a small-model judge, called only when the reply addresses the owner; inside my authority: decide; otherwise AskUserQuestion with each option self-contained, never a pointer to an earlier message; an action only the owner can perform, such as a typed `APPROVE <hash>`, stays text with the exact action), a completion claim without its observation, a first-person promise of later work with no issue, PR or handoff file that existed before this turn naming it, and (rule `next-step`) a reply whose closing part names the agent's own next step (a next-step label, a first-person future verb, a list of the checks that would decide the open question, or a check named as not yet run) while no background task, Monitor, one-shot Cron pending its time or agent of the session is still live, when the judge finds the step could start now; and (rule `timed-step`) a reply whose closing part names a step of the agent's own at or after a clock time, date, night or period that has not arrived (a relative time word, or a date or HH:MM after a forward word, in the same sentence as a first-person step verb or a next-step label) while nothing wakes the session on a clock (a live one-shot or recurring Cron job, or a pending `/loop` wakeup; a Monitor or agent is not a clock), when the judge finds an own step at that time not gated as a whole on the owner's word; the return asks for one `CronCreate` one-shot (id, fire time, `CronList`, session exit kills it) or a statement that nothing of the agent's runs before the owner's word. With no judge (rule `first-cause`): a reply whose first paragraph (up to the first blank line, backticked spans removed, typed or untyped, an `Unknown:` line included) holds a non-negated causal connective, an asserting cause noun (`по причине`, «причина та же», `the cause was`) or a past-tense cause verb whose clause names no agent subject before it («я», «мы», a script, worker, agent, hook, job, cron or command), except a cause word right after «что» / «что именно» / `what` in an `Unknown:` question; an `Unknown:` paragraph (label plain, bold or backticked) holding a why-word («почему», «отчего», «из-за чего», `why`) outside quoted spans is returned with no exemption; a reply that opens with `Proven:` passes only in its full form (`explains <X> of <Y>` with counts, 1 <= X <= Y) and then passes whole. The return does not quote the matched word: it keeps the effect a read showed under `Fact:`, moves the cause below the first paragraph as a labelled hypothesis with its deciding read, offers `Unknown:` only for a blocked read and `Proven:` only after a read that rules out the other causes, and says once that the last message of the turn opens with the corrected (or kept) first paragraph. It returns at most twice per turn: on a later stop, only when the transcript shows a Stop hook return in this turn and fewer than two of them were `first-cause`; an unreadable transcript passes. English and Russian words only. The return asks for an addendum with only the missing part, not a repeat of the reply.
- Stop hook `background-watch-gate` (main session): returns the stop once when a background Bash task is open (no completion notice, no TaskStop), unwatched (no Monitor armed after it and still live, no `CronCreate` after it), and launched this turn or its last Monitor ended this turn; a launch that is only a wait is exempt: `wait-for`, a bare `sleep`, `tail -f`, or a loop whose condition runs a script of the session (a loop on any other probe, such as `until gh pr checks ...; do sleep 20; done`, fires); the second stop passes on its marker; log `~/.claude/background-watch-log.jsonl`.
- A hook `ask` does not prompt in bypass-permissions mode. A Claude Code config directory other than `~/.claude` (set by `CLAUDE_CONFIG_DIR`) does not load hooks from `~/.claude/settings.json`.
- `loop-cost-gate` (PreToolUse, PostToolUse, PostToolUseFailure on Bash; main session and agents): journal `~/.claude/loop-cost/<sha1 of the repository root>.jsonl`, all worktrees pooled, rows older than the 6 h window ignored. Key: basenames of the programs run after shell comments, wrappers (`cd`, assignments, `env`, `time`, `nohup`, `timeout`, `nice`, `caffeinate`, `sudo`, `xargs`, `stdbuf`, `rtk`, `check-run --`, `wait-for ... --`, `secretctl ... --`, interpreters and their flags, `sh -c`), pipe filters and small file tools are removed. A `wait-for` is journaled (its minutes count toward the repository's total) but never refused. The refusal folds the window by key and lists prior acknowledgements; the `# LOOP_COST:` reason is journaled as an acknowledgement for that key and restarts its count and the repository's minutes; a subagent carries the reason into its reply's deviations. Defaults in `orchestrate-params.json` `loop_cost`.

## Destructive

Classified by the orch hook `deny-destructive.py` (policy `gate_policy.destructive_decision`, table in `orchestrate-params.json`), never by the agent; no text an agent writes raises a decision.

- `ours`: paths under `/tmp`, `tmp/`, `.worktrees/`; k8s objects with the `orch.session` label; live writes with a cheap mechanical undo on one named object (`kubectl scale`, `kubectl rollout restart|undo|pause|resume`; with `--all`, a selector, several objects or `-f`/`-k` they are `approval`). Runs without a prompt. Flux reconcile/suspend/resume is unclassed and runs.
- `approval`: a live write whose undo is not mechanical (SQL writes, `kubectl apply/delete/patch`). Runs only from one plan script with `# scope / # undo / # count / # contradiction / # prod_position / # way_back / # effect_read` headers (`# effect_read`: how the command's effect on the whole object was read: the code down to the write call, or a dry-run, `kubectl diff` or scratch-object run with the resulting object compared to the current one; `--help` or a hook's recommendation is not that read; a wrapper that runs or performs a live write carries the gate of the raw command), run from the main session as `bash <abs path>  # DESTRUCTIVE_PLAN sha256=<hash>` (that one line, whole-line `#` comments allowed around it; the plan takes no arguments and redirects its own output; a command whose top level carries the marker in comment position either is that form or is refused), after the owner's approval of the plan: the permission prompt, or `APPROVE <hash>` where the session cannot prompt. Work of several steps is two plan files at most: a pilot, then one file that runs every remaining step in order and stops on its own checks; a step is never a separate file or a repeated approval of the same text.
- Reads pass unclassed when the server enforces them: `clickhouse-client --readonly=1`, or psql SQL that starts with `BEGIN READ ONLY;` and has no COMMIT, ROLLBACK, SET TRANSACTION, `transaction_read_only`, RESET ALL or backslash command (no `-1`). A job of the same command stops with `kill $!`, `kill %1` or a name bound to `$!`.
- `impossible`: no undo (DROP/TRUNCATE, Secret replace, namespace/PVC delete, force push, rm outside ours). Refused as a bare command; it runs only from an approved plan that states what it does.

## Waits

A wait on a condition: run the condition once (`wait-for` exits 2 on a broken command), then one Monitor in the main session (up to 60 minutes; re-arm on the same run if it times out while the job lives). A wait until a clock time, or longer than one Monitor (a deploy window hours away, a nightly pass): one `CronCreate` one-shot at that time, session-only, its prompt carrying the check and the steps or the handoff path; `/schedule` when the session may close before then. Never an LLM that ends its turn to wait; never a poll loop, a `sleep` until the time, or monitors re-armed every hour. The reply names the mechanism: tool, task id, fire time, `CronList` to see it, session exit as what kills it, and the handoff file for that case.

## Secrets

The vault is managed by `~/.claude/tools/secretctl` (`list` / `run` / `each` / `import`; `run` and `each` pass `$SECRET_VALUE` by reference). `secret-vault-gate` refuses direct reads of the vault, Secret payloads and known values in tool inputs; `redact-secrets` masks known values and key-shaped tokens in Bash/Read/Grep results.
