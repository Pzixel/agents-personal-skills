# A fix is proven at the layer where the decision lives, not by a production send

Decision (2026-10-31, retro-evals CASE-51): the Measurement bullet "A fix is proven at the layer where the decision lives …" in `rules/always-on.md`, plus one sentence in the orchestrate `proof` paragraph.

Why. Session cb622f52 (proxy #79, a five-line MIME fix in a pure function `RewriteEmail(bytes, domain) -> bytes`) spent 04:27Z–10:22Z on "verifying on a real mail": two builders, two owner questions, a campaign send from a client workspace whose domain had link rewriting off, a counter that stayed 0, and the claim "the fix is not verified on a real mail". The owner's question "is a physical send needed at all? where is the decision made?" produced, in two minutes, the native run of the function on the archived real mail under old and new code (old drops the text after the last `--` line, new keeps all 26/28 lines and rewrites the links). The rule the agents had ("pure policy … proven independently") governs code shape; nothing said that the proof of a fix follows the same layering, and "Done = original scenario re-checked on production" was read as "a production send is the proof".

Compared against. v1 "one run on the real system, preconditions read from its result" (retro-evals runs/one-run, six subject runs, not graded): it fixes the gates and the stop rules but keeps the production send as the first step; under the v1 packet none of twelve subjects proposed the function run. Rejected after the owner's second point. v2 (this bullet) measured on the amended packets: CASE-51 0/3 -> 3/3, CASE-51B 1/3 -> 3/3, controls CASE-4 3/3 held, CASE-41 0/3 held, CASE-5 0/3 -> 3/3, CASE-7 3/3 and 14 % shorter (retro-evals runs/by-layer/RESULT.md).

Boundary. The production run is still required for the wiring (config, gate, path) when the fix touched it, and it stays one run read where the user reads it; a run that is itself the harm (a send to a client's lead, a write without undo) keeps its precondition proof. "Real" in an owner's "check it on a real mail" means the real artifact, not the production path, unless the owner names the path.
