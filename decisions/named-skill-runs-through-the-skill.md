# A step named by a skill runs through the skill, never through the agent's paraphrase of it

Decision: when the owner or the plan names a step by a skill's name (`simplify`, `test-audit`), or a listed skill's description covers the step, the agent loads that skill and follows its procedure (lenses, phases, agent count) at the named target. A paraphrase of the skill from memory (an own lens list, a "section" in a note, one reviewer blending the lenses) is the defect, however close it comes. When the skill's stated target differs from the task's (the skill says «changed code», the owner wants the plan), the target is adapted in the skill's arguments or the agents' prompts and the procedure is kept. The property lives in `rules/always-on.md` (Scope). The plan-level `/simplify` mechanism already exists (`decisions/plan-simplify-fan-out-by-plan-size.md`, reviewer lenses on design documents); this rule covers the main session's choice to run a named skill at all.

Why: session 2026-10-21 (private retro-evals CASE-27, K39). Owner: «Прежде чем писать код не забудь план + simplify», then «simplify не после кода а после плана. До кода». The main session gave the builder a «"simplify" section: can it be removed or reused» (one home-made lens), then ran one reviewer with «Lens: reuse, removal, altitude» (three lenses, one invented, two of the skill's four missing), with the `simplify` skill listed in its system prompt and one `Skill` call away. Owner: «simplfy pass использует линзы из скилла? Иначе это ерунда»; after the correction the skill's efficiency lens, absent from the paraphrase, returned the pass's only MAJOR. Owner, retro: «агент никогда не должен использовать "свой набор линз", нужно пользоваться скиллом».

Compared against:
- No rule, rely on the skill listing in the system prompt: that is the state in which the failure happened twice in three minutes; the listing was in front of the agent both times. Rejected.
- A rule naming `simplify` only: the owner's criterion is general («нужно пользоваться скиллом»), and the same shape (a named procedure replaced by its summary) applies to `test-audit`, `pareto-design-selection`, `infra-access`. Rejected as the case restated.
- Text harness, 2026-10-21, one blind grader, k=3 per arm. Round 1 packet (after the owner's correction, skill described in the packet): baseline 3/3, non-discriminating. Round 2 packet (the earlier point, skill in the listing by name only): baseline 1/3 (two subjects load the skill and then run their own table; one is ready to call the skill inapplicable to a plan and substitute its own pass), with the bullet 3/3. Controls CASE-23 3/3 → 3/3, CASE-5 6/6 → 5/6 (one run, the repeat 3/3 both arms). Accepted by the pre-registered rule (`runs/skill-line/RESULT.md` in private retro-evals).

Size: always-on +81 words / 477 characters, nothing removed. Live check: the next task where the owner or the plan names a skill, in a fresh session — the skill is loaded before the pass is dispatched and the agents' prompts carry its procedure.
