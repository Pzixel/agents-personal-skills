# A wait until a clock time is one CronCreate one-shot, and the reply names it

Decision (2026-10-21). A wait on a condition stays one Monitor (details "Waits"). A wait until a clock time, or longer than one Monitor's hour, is one `CronCreate` one-shot at that time, session-only, with the steps in its prompt and the handoff path for the case the session closes; `/schedule` only when the session may close before the time. Never a poll script, a `sleep`, a `watcher` polling for hours, or monitors re-armed every hour. The reply that promises the later action names the mechanism: tool, task id, fire time, `CronList` as the way to see it, session exit as what kills it.

Why. Session backend ee3bf91a (proxy #74, deploy window nine hours away): the loaded rules named Monitor, `watcher` and a few minutes of `wait-for` and nothing for a clock time, so the agent first wrote a `while … sleep 300` poller (refused by the hook) and found `CronCreate` only after the refusal; its reply then said «проснусь по таймеру» and the owner, seeing no timer, monitor or shell in the terminal, could not tell the promise was backed (retro-evals K41, K42). A session-only cron task is not on disk, not in the background-task list and not in the status line; only `CronList` shows it.

Measured (retro-evals, CASE-29 and CASE-29B, k=3, one joint blind grader per case, 2026-10-21): baseline 0/3 on both (CASE-29: fire time with no tool, id or way to see it; CASE-29B: an `orch:watcher` polling every 5–10 minutes for nine hours); with the bullet 3/3 on both (one `CronCreate` at 21:00 UTC, `CronList` named, session exit named). Controls: see retro-evals runs/wait-mechanism-ctl29/RESULT.md.

Compared against. (a) Hook text only: not measurable in a text packet and reaches the agent only after a wrong call; kept as the second layer, so the refusal now names the right mechanism. (b) A line in `reply-lint` requiring a mechanism for any promise: the judge already accepts a promise that names a handoff file, which this reply did; the defect was the missing tool name, which the always-on bullet fixes at the source. (c) A `/schedule` cloud routine by default: a fresh cloud clone has no access to the cluster or metrics for the check, so it fits only the case where the session may close.
